# Busy Codex

Codex task state, current account limits and elapsed quota-window
progress on a BUSY Bar. Turn the dial to change the reasoning effort of the
foreground Codex Desktop task or supported CLI session. The display reflects
the confirmed setting; each effort level has its own native animation.

This is an independent community app, not an OpenAI or BUSY Bar product.

## Run

Download this **complete folder**. Python 3.9 or later is the only runtime
dependency; there are no pip packages to install.

```sh
python3 app.py                            # USB at 10.0.4.20
python3 app.py --host 192.168.1.50         # Wi-Fi
python3 app.py --host 127.0.0.1:8080 --demo # emulator, synthetic data
python3 app.py --test                     # one synthetic frame, then exit
```

For an authenticated Wi-Fi Bar, set `BUSYBAR_TOKEN` in your environment. For a
non-default Codex installation, set `CODEX_HOME` and/or `BUSYBAR_CODEX_BIN`.
Authentication stays with the installed Codex executable.

Normal startup uploads this app's native animation assets to the Bar. It does
not install an APPS-menu entry, a login item or a system service. Subsequent
starts may use `--no-upload` while the packaged assets remain on the device.

The app owns a loopback report endpoint on port 18765; use `--port` to choose
another. Stop any other busy-codex instance before giving this one the dial.
`--no-effort` leaves the app in read-only mode. Ctrl-C or SIGTERM stops the
owned workers, releases its canvas and does not restart either process.

## Codex compatibility

- **Codex Desktop on macOS:** follows the task open in the foreground window.
  Effort uses the Desktop's local IPC interface, which is private and may
  change between Desktop releases.
- **Codex CLI:** account limits can be read with stock CLI. Reliable effort
  switching and terminal session targeting require the
  [native-control fork release](https://github.com/wowlocal/codex/releases/tag/v0.153.4-fork.1-native-control).
  It exposes a local, same-user Unix socket with versioned status and confirmed
  effort changes. No terminal keystroke injection or config-file rewriting is
  used. Foreground app/terminal selection is currently macOS-specific.
- **No Codex installed:** `--demo` and `--test` run without opening Codex files,
  processes, credentials or network services.

Session state is read from local Codex metadata. Account limits come from
`account/rateLimits/read` through a short-lived local Codex app-server, refreshed
once a minute. No model inference or prompt submission is performed. Missing
or expired quota data remains unavailable instead of being shown as zero.

## Preview and conformance

In a busybar-apps checkout:

```sh
npm run check -- busy-codex --run -- --demo
python3 tools/busyrec.py apps/busy-codex --seconds 8 --steal-at 3 -- --demo
npm run preview -- busy-codex --seconds 7.2 --fps 9 -- --demo
npm run build
```

The preview is actual output from `--demo`, captured by the gallery recorder.
Demo mode streams PNGs generated by the same pixel renderer as the native
`.anim` files. Normal mode uploads the animations once and plays them on the
device at 25 fps, avoiding constant frame traffic. The PNG demo transport is
also compatible with the gallery renderer's more limited `.anim` decoder.

The adjacent Python modules and assets are a reproducible snapshot of
[busy-codex](https://github.com/wowlocal/busy-codex), built with
`python3 scripts/build_gallery.py --output /path/to/apps/busy-codex`.
`SOURCE.json` records SHA-256 hashes for review. Generated files should be
updated from the upstream project instead of patched independently here.
